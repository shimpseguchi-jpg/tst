# くりあがりピンボール

小学1年生の算数「10をこえるたし算・ひき算（くりあがり／くりさがり）」を、
ピンボールで練習するブラウザゲームです。iPad（Safari / Chrome）でのタッチ操作前提。

`index.html` 1ファイルだけで動きます（外部ライブラリ・通信なし）。

## ゲームの内容

- 画面上部に問題が出ます（例：`8 + 5 = ?`）
- 盤面のバンパー3つに数字が書かれていて、そのうち1つが正解
- 正解のバンパーにボールを当てると得点＋次の問題へ
- まちがえると「さくらんぼ計算」のヒントが数秒だけ自動で出ます
- 5問正解ごとにレベルアップ（ボーナス点＋ボール1個追加）
- ボールを3個おとすとゲームおわり

### 算数のねらい

| 要素 | ねらい |
|---|---|
| さくらんぼ計算の図 | `8 + 5` の `5` を `2` と `3` に分ける手続きを見える化 |
| 10のまとまり（ten-frame） | 「10をつくる」→「10といくつ」の量感をつかむ |
| 手順の式 | `8 + 2 = 10` / `10 + 3 = 13` を並べて確認 |
| ひき算 | 減加法（`16 - 7` → `10 - 7 = 3` → `3 + 6 = 9`）で表示 |
| 選択肢 | まちがいの選択肢は ±1 / ±2 や「くりあがりを忘れた答え」など、つまずきやすい値 |

出題範囲：
- たしざん … くりあがりのあるもの（答えは 11〜18）
- ひきざん … くりさがりのあるもの（答えは 2〜9）
- ミックス … 上の2つをランダムに

## そうさ（iPad）

| したいこと | そうさ |
|---|---|
| スタート | 画面をタップ |
| はっしゃ | 画面を押しつづけて力をためる → はなす |
| 左フリッパー | 画面の**左半分**をタップ（押しっぱなしで上げたまま） |
| 右フリッパー | 画面の**右半分**をタップ |

2本指で左右同時に押せます。パソコンでは ←→ キーとスペースキーでも遊べます。

ボタン：`たしざん` `ひきざん` `ミックス`（出題の切りかえ）、`ヒント`（さくらんぼの表示を固定）、`さいしょから`。

## Google サイトへの埋め込み

Google サイトの「埋め込みコード」は**約1万文字までしか貼れない**ため、
このファイル（約28KB）はそのまま貼りつけできません。
どこかに置いて **URL を埋め込む** かたちにします。

### 方法A：GitHub Pages（無料・おすすめ）

1. このリポジトリの **Settings → Pages** を開く
2. *Source* を **Deploy from a branch**、ブランチをこのブランチ（または `main`）の `/ (root)` にして保存
3. 1〜2分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される
4. Google サイトの編集画面で **挿入 → 埋め込む → URL** にそのアドレスを貼る
5. 挿入されたブロックの角をドラッグして、**たてに長く**（横幅いっぱい・高さ 700px 以上）広げる

`挿入 → 埋め込む → 埋め込みコード` を使う場合はこちら（URL は自分のものに置きかえ）：

```html
<iframe src="https://<ユーザー名>.github.io/<リポジトリ名>/"
        style="width:100%;height:760px;border:0;display:block"
        allow="autoplay"
        title="くりあがりピンボール"></iframe>
```

### 方法B：Netlify Drop など

`index.html` を https://app.netlify.com/drop にドラッグするだけでも URL が発行されます。
あとは方法Aの手順4以降と同じです。

> Google ドライブに置いた HTML は現在ウェブページとして表示できません（埋め込み不可）。

### 埋め込むときのコツ

- 高さは **700〜900px** 推奨。低いと盤面が小さくなります
- 端末が横向きのときは、問題文が右側に回り込むレイアウトに自動で切りかわります
- 音は最初のタップのあとに鳴ります（ブラウザの仕様）

## 盤面の配置について

バンパー（まと）3つとピンの位置は、当てずっぽうではなく自動探索で決めています。
`index.html` から物理演算のコードをそのまま取り出して Node で動かし、
約1200案 × 各400球ぶんプレイさせて比べました（`tools/layout-sim.js`）。

見ている指標:

| 指標 | ねらい | 採用案 |
|---|---|---|
| 3つのまとの当たり分布 | どれが正解でも公平に狙えること（ここが偏ると運ゲーになる） | 34 / 33 / 33 % |
| まとに一度も当たらない球の割合 | 「何もできずに終わる」球を無くす | 0.7% |
| 発射から最初に当たるまで | すぐ反応が返ること | 約1.5秒 |
| 1分あたりのヒット数 | 忙しすぎず暇すぎず | 約27回 |
| 1球の長さ | 短すぎると練習にならない | 約21秒 |
| 停滞時間 | どこかに挟まって動かなくならないか | 最長0.1秒 |

最初の案（まとが下寄りの三角形）は、当たり分布 36/28/36、
まとに当たらない球が9%、初ヒットまで3.3秒でした。
採用案（上に2つ・中央下に1つの逆三角形＋中央脇のピン2本）に変えたことで、
実ブラウザでの90秒自動プレイが **26ヒット/13問正解 → 57ヒット/25問正解** になりました。

中央脇のピン2本は見た目のためではなく、
外すと当たり分布が 35/30/34 に崩れる（均等さ 0.99 → 0.86）ので必要です。

### 自分で調べなおす

```
node tools/layout-sim.js check            # いまの配置を評価する
node tools/layout-sim.js search 200 60    # 200案をランダムに作って上位10案を出す
```

`index.html` の物理コードを読みに行くので、重力やフリッパーをいじれば評価もそれに追従します。

## 中身をかえる

`index.html` の上のほうにまとまっています。

| したいこと | 場所 |
|---|---|
| 出題の範囲をかえる | `makeProblem()` の `ri(5,9)` などの数字 |
| まちがいの選択肢をかえる | `choicesFor()` の `cand` の配列 |
| ボールの数 | `resetGame()` の `G.balls=3` |
| レベルアップの間隔 | `hitBumper()` の `G.correct % 5` |
| 盤面のかたち | 先頭の `walls` / `bumpers` / `posts` / `flippers`（変更後は `layout-sim.js check` で確認を） |
| むずかしさ（球速） | `GRAV`（大きいほど速い）と発射の `1150 + 520*G.power` |
