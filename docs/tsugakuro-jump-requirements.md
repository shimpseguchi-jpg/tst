# つうがくろジャンプ ― 要件定義書（v0.1 ドラフト）

小学1年生の算数（1〜30のたし算・ひき算／かたち）を、
日本の通学路を舞台にした2D横スクロールのジャンプゲームで練習するアプリ。
Google Apps Script（GAS）のウェブアプリとして公開する。

- ゲーム名：**つうがくろジャンプ**（仮称）
- 前作：`くりあがりピンボール`（`index.html`）。操作感・ヒント表現・計測の作法はそこから引き継ぐ。

---

## 0. この文書の使い方

「決定」と書いた項目は実装の前提として確定。
「暫定」は数値を仮置きしてあるので、実機（iPad）で触って調整する。
「未決」は §13 に集めた。ここが埋まらないと手戻りが出る。

## 1. 目的とゴール

### 1.1 なにを達成したいか

| | 内容 |
|---|---|
| 学習のねらい | 答えが1〜30になるたし算・ひき算を、**考えこまずに出せる**ところまで持っていく。あわせて「かたち」の見分けを身につける |
| 体験のねらい | 算数の時間ではなく**ゲームの時間**だと本人が思っている状態にする |
| 運用のねらい | Googleサイトに貼るだけで、複数の子どもがそれぞれの進み具合で遊べる |

### 1.2 成功の定義（リリース後に見る数字）

- 1人あたりの1回の起動で **算数20問以上**に触れている
- **自分から2回目を起動する**（1回遊んで終わりにならない）
- くりあがりのたし算の正答率が、使い始めから2週間で上がっている

### 1.3 やらないこと（明確な非ゴール）

- 教科書の代替にはしない。**練習用**であって、新しい単元をここで初めて習うことは想定しない
- 対戦・ランキングによる競争はしない（1年生には劣等感の芽になりやすい）
- 広告・課金・外部サービス連携はしない

## 2. 決まっていること（前提）

| 項目 | 決定内容 |
|---|---|
| 算数の出し方 | **走りながら選ぶ足場型**。3つの足場／ブロックに数字が書かれ、正解に乗る（叩く）と進める |
| 図形の扱い | **クイズとして出す**＋**ゲームの仕組みに溶かす**、の両方 |
| 配信方法 | GASウェブアプリ。**Googleサイト等への埋め込み**が前提 |
| 利用形態 | **複数の子ども／クラス**で使う。ひとりずつ進み具合を分ける |
| 1回の長さ | **1ステージ2〜3分** × 複数ステージ。1ステージあたり算数10問前後 |

## 3. 対象と利用環境

### 3.1 対象

- **主対象**：小学1年生（6〜7歳）。ひらがなは読める。カタカナと漢字は読めない前提
- **副対象**：年長〜小学2年生（復習）
- **見守る人**：保護者、または担任の先生

### 3.2 利用環境（決定）

| | 内容 |
|---|---|
| 端末 | **iPad（Safari / Chrome）横向き**を第一想定。前作と同じ |
| 副 | PC（キーボード操作）、Androidタブレット。スマホは画面が小さく非推奨だが動くこと |
| 置き場所 | Googleサイトに iframe 埋め込み（高さ700〜900px）。GASのURLに直接アクセスしても遊べる |

| Googleログイン | **不要**（ウェブアプリのアクセス範囲を「全員」にする）。学校の共有アカウント運用に耐えさせる |

## 5. 学習要件

### 5.1 単元と数の範囲（決定）

答えが 1〜30 の範囲を、教科書の進度順に6つの型に分解する。

| 型 | 内容 | 式の例 | 答えの範囲 |
|---|---|---|---|
| A | くり上がりのないたし算 | `3 + 4` | 1〜10 |
| B | くり下がりのないひき算 | `9 - 4` | 1〜9 |
| C | 3つの数の計算 | `3 + 2 + 4` / `10 - 3 - 2` | 1〜10 |
| D | くり上がりのあるたし算 | `8 + 5` | 11〜18 |
| E | くり下がりのあるひき算 | `13 - 6` | 2〜9 |
| F | 20より大きい数 | `20 + 7` / `23 + 4` / `27 - 3` | 20〜30 |

補足ルール：

- 型Fの `23 + 4` は**くり上がりを起こさない**ものに限る（1年生の範囲を超えるため）
- 引かれる数・足される数はいずれも 30 以下
- `0` を含む式は型A・Bで各ステージ1問まで（意味は理解しにくいが出会わせておく）

### 5.2 かたち（図形）の範囲（決定）

1年生の「かたち」は立体と平面の2本立てなので、両方入れる。

| 区分 | 内容 | ゲームでの見せ方 |
|---|---|---|
| 立体 | はこのかたち／つつのかたち／ボールのかたち | 「つめる・ころがる・つむ」性質をギミックにする（§6.5） |
| 平面 | まる／さんかく／しかく | 通学路の風景から形を見つけるクイズ |
| かたちづくり | いろいた（三角2枚で四角、など） | パズルステージ |

### 5.3 ステージと単元の対応（決定・全11ステージ）

| # | ステージ名 | 舞台 | 単元 | 問題型 |
|---|---|---|---|---|
| 1 | いえを でる | 朝の住宅街・ブロック塀 | あわせて いくつ | A |
| 2 | いぬの いる みち | 路地・電柱 | のこりは いくつ | B |
| 3 | こうえんを ぬける | 公園の遊具 | 3つの かずの けいさん | C |
| 4 | **かたちの こうえん** | 公園（すべり台・ジャングルジム） | かたち（まる・さんかく・しかく） | 図形 |
| 5 | かわの どて | 土手・たんぽぽ | くりあがりの たしざん | D |
| 6 | しょうてんがい | アーケード商店街 | くりさがりの ひきざん | E |
| 7 | ふみきり | 踏切・電車 | たしざん・ひきざん ミックス | D+E |
| 8 | **かたちの まちかど** | 看板・標識・マンホール | かたちづくり（いろいた） | 図形 |
| 9 | ほどうきょう | 歩道橋の階段 | なん十と いくつ | F |
| 10 | あめの みち | 雨・水たまり・かさ | 2けた ± 1けた | F |
| 11 | がっこうの もん | 校門・校舎 | ぜんぶ ミックス | A〜F |

MVPは 1〜6。ステージ4（かたち）はMVPに入れるかを §13 で確認。

### 5.4 出題アルゴリズム（決定）

1問は `{ 式, 正解, 誤答2つ, 正解の位置 }` で構成する。

- **1ステージの問題数**：10問（暫定。§12の時間基準に合わせて8〜12で調整）
- **重複禁止**：同一ステージ内で同じ式を2回出さない
- **正解位置の公平さ**：左／中／右の出現率が各 33%±5% に収まること。**同じ位置が3回続かない**
  （前作で当たり分布の偏りを潰した経験を、そのまま持ち込む）
- **やりなおし時**：同じ式を再提示するが、**数字の並びだけシャッフル**する（位置を覚えて突破させない）
- **まちがえた式の再挑戦**：そのステージ内で、3問あとにもう一度出す（1回だけ）

### 5.5 誤答の選択肢の作り方（決定）

でたらめな数字は出さない。**その子がやりそうな間違い**を置く。前作 `choicesFor()` の方針を引き継ぐ。

| 型 | 誤答に置く値 |
|---|---|
| A・B | 正解 ±1、±2（数え間違い） |
| C | 3つ目を足し忘れた値、途中結果そのもの |
| D | **くり上がりを忘れた値**（`8+5` → `3`）、正解 ±1 |
| E | **引く順を逆にした値**（`13-6` → `7` に対し `3`）、正解 ±1、たし算してしまった値 |
| F | **位を取り違えた値**（`23+4` → `63`）、一の位だけ計算した値 |
| 図形 | 名前が似ている形（さんかく／しかく）、性質が近い形（つつ／ボールはどちらも転がる） |

制約：誤答は 0 以上・負の数を出さない。3つの選択肢はすべて異なる値にする。

### 5.6 まちがえたときの支援（決定）

**まちがえてもゲームオーバーにしない。** ここは学習アプリとして譲らない。

| 回数 | 起きること |
|---|---|
| 1回目 | 足場が崩れて下の道に着地（ダメージなし）。前作と同じ**さくらんぼ計算のヒント**が数秒表示される |
| 2回目 | ヒントが**10のまとまり（ten-frame）の絵**つきで、消えずに出たままになる |
| 3回目 | **正解の足場が点滅して教えてくれる**。乗れば進める（ここで詰まらせない） |

- ヒントの出し方は前作 `index.html` の表現をそのまま流用する（`8 + 5` の `5` を `2` と `3` に分ける図）
- ひき算は減加法（`13 - 6` → `10 - 6 = 4` → `4 + 3 = 7`）で表示
- 型Fは「10のまとまりがいくつ」の絵（10のかたまり＋ばら）で表示
- 図形は、実物の絵（はこ＝ティッシュ箱、つつ＝かんジュース、ボール＝ボール）を並べて示す
- **「まちがい」という言葉を使わない**。「おしい！」「もういちど」にする

## 6. ゲーム要件

### 6.1 コアループ（決定）

```
名前をえらぶ → ステージをえらぶ
   ↓
走る → 3択の足場が近づく → 問題を読む → ジャンプして正解に乗る
   ↓                                         ↓ まちがえた
コイン＋1 ────────────────────── ヒント → もういちど
   ↓  （これを10問くりかえす）
校門（ゴール）に とうちゃく → ★評価 → シールがもらえる → 進捗を保存
```

### 6.2 操作（決定）

| したいこと | iPad | PC |
|---|---|---|
| 右へすすむ | 画面左下の「→」ボタン、または画面右半分を押しっぱなし | `→` キー |
| 左へもどる | 画面左下の「←」ボタン | `←` キー |
| ジャンプ | 画面右下の大きな丸ボタン | スペース／`↑` |
| ポーズ | 右上の ⏸ | `Esc` |

- **自分で走る方式**（オートランにしない）。**立ち止まって考えられること**が1年生には必須
- ボタンは**直径80px以上**、画面下端から24px以上離す（持ち手の親指が届く位置）
- 2本指同時押し（移動＋ジャンプ）に対応する
- **ジャンプは押した長さで高さが変わる**（マリオらしさの核。短押し・長押しで2段階以上）

### 6.3 主人公とアクション（決定）

- ランドセルを背負った子ども。**性別を特定しない見た目**にする（帽子＋ランドセル）
- 動きのパラメータ（暫定・実機で調整）

| 項目 | 暫定値 |
|---|---|
| 論理解像度 | 960 × 540（表示は画面幅にフィット、DPR対応） |
| 主人公のサイズ | 幅 36px × 高さ 52px |
| 走る速さ | 200 px/秒（最高速まで0.2秒で加速） |
| ジャンプの高さ | 短押し 70px／長押し 115px |
| 滞空時間 | 長押しで約0.75秒（水平移動 約150px） |
| 重力 | 落下は上昇の1.4倍の加速（もっさりさせない） |
| コヨーテタイム | 足場を離れてから0.1秒はジャンプ可（1年生の押し遅れを許す） |
| 先行入力 | 着地0.15秒前のジャンプ入力を受け付ける |

> コヨーテタイムと先行入力は**必ず入れる**。これがないと「押したのに跳ばない」と感じて操作のせいで挫折する。

### 6.4 算数ギミック：3択の足場（決定・本作の中心）

**配置**

```
          [ 12 ]   [ 13 ]   [ 11 ]     ← 3つの足場（横ならび）
   🧒 →                                 ← 主人公は下の道を走る
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
                    ↑ まちがえたらここに落ちるだけ（ダメージなし）
```

| 項目 | 仕様 |
|---|---|
| 並び | **横ならび3枚**（縦積みにしない。ジャンプ力の微調整が必要になり難しすぎる） |
| 足場の大きさ | 幅 80px × 高さ 20px（暫定）。数字は足場の上に大きく表示 |
| 足場どうしの間隔 | 60px（ジャンプ水平移動150pxより十分せまい＝どれにも届く） |
| 足場の高さ | 地面から 75px（長押しジャンプ115pxより低い＝必ず届く） |
| 問題文の表示 | 画面上部のHUDに固定（`8 + 5 = ?`）。足場が画面に入る**前**から見えている |
| 正解したとき | 足場が光る／コイン＋1／効果音／次のセクションへスクロール |
| まちがえたとき | その足場だけ**ふにゃっと消えて**下の道に着地。§5.6のヒント |
| 落下死 | **なし**。下は必ず地面。穴は作らない（算数セクションでは） |

**時間の保証（重要）**

- 問題文が画面に出てから足場に到達するまで、走り続けても **最低4.0秒**あること
- 立ち止まれば**時間制限はない**（タイマーで急かさない）
- ★評価にはタイムを使うが、**遅くても★1は必ずもらえる**

**バリエーション（見た目だけ変える。仕組みは同じ）**

| ステージ | 見た目 |
|---|---|
| 1・2 | ブロック塀の上の 3つのブロック |
| 3 | 公園のジャングルジムの 3つの段 |
| 5 | 土手に生えた 3つの切りかぶ |
| 6 | 商店街の 3つの日よけテント |
| 7 | 踏切の 3つの標識 |
| 9 | 歩道橋の 3つの踊り場 |
| 10 | 3つの かさ |
| 11 | 校門の 3つの旗 |

マリオの「？ブロックを下から叩く」型も**ステージ2・6で1セクションだけ**混ぜる（仕組みは同じ3択）。

### 6.5 図形ギミック（決定）

**(a) 仕組みに溶かす — 全ステージ共通の物理**

| かたち | ふるまい |
|---|---|
| **はこのかたち**（直方体） | 押せる。積める。上に乗れる。**転がらない** |
| **つつのかたち**（円柱） | 横に置くと**転がる**。立てると乗れる。積むと不安定 |
| **ボールのかたち**（球） | 坂を**転がって追ってくる**。乗れない |

これで「なぜ箱は積めてボールは積めないのか」を手で覚える。ステージ3・4に配置する。

**(b) かたちクイズ — ステージ4・8**

- 3択の足場に**数字でなく形**が描かれている。問題文は「**ころがるのは どれ？**」「**さんかくは どれ？**」
- 通学路の風景から探す型：「この みちで **しかく**の かたちは どれ？」→ 看板・マンホール・標識を選ぶ
- 出題パターン：
  1. 名前 → 形（「さんかくは どれ？」）
  2. 性質 → 形（「ころがるのは どれ？」「つめるのは どれ？」）
  3. 数える（「この かたちは さんかく いくつ？」）

**(c) かたちづくりパズル — ステージ8**

- いろいた（三角形の色板）を2〜4枚ならべて、お手本の形（しかく・おうち・さかな）を作る
- ドラッグ＆ドロップ＋回転（タップで45度ずつ）。**スナップ機能を必ず入れる**（1年生に精密なドラッグは無理）
- アクションは止まる。ここだけはパズル画面として独立させる

### 6.6 通学路の風景とギミック（決定）

| 要素 | 内容 |
|---|---|
| 背景 | ブロック塀、電柱、カーブミラー、こども110ばんの家のプレート、自動販売機、アーケード、土手、田んぼ、踏切、歩道橋、校門 |
| 足場 | 縁石、階段、土手の斜面、ベンチ、跳び箱のようなブロック、日よけテント |
| 障害 | 水たまり（濡れると遅くなる／ダメージなし）、伸びた雑草、置き石、工事のコーン |
| 生きもの | カラス（前を横切る）、ちょうちょ、ねこ、セミ |
| 集めるもの | コイン、**きゅうしょくの おかず**（ボーナス）、シール |
| 待つギミック | **信号**（赤のあいだ止まる → 青で進める）、**踏切**（電車が通り過ぎるのを待つ） |

### 6.7 交通安全の表現ルール（決定・必読）

舞台が実在する通学路である以上、**ゲームの中でやったことを現実でやる**危険がある。次を絶対ルールにする。

| ルール | 内容 |
|---|---|
| 車道に出ない | 主人公が走るのは**歩道・土手・公園・空き地のみ**。車道を横切るアクションは作らない |
| 車を障害物にしない | 走っている車をジャンプで避ける／踏むギミックは**作らない** |
| 信号は待つ | 赤信号は「待てば必ず青になる」ギミック。**無視して進む選択肢を用意しない** |
| とび出しは失敗 | 塀の陰から飛び出すような動きは、ゲーム上でも**止められる**演出にする |
| 踏切は待つ | 遮断機が下りているあいだは進めない。くぐる操作を作らない |
| 生きものを踏まない | 敵を踏んで倒す表現は使わない。カラスは近づくと飛び去るだけ |

信号・踏切の「待つ」は、**待っているあいだに次の問題を読める時間**にもなる。学習と安全が両立する良いギミックなので積極的に使う。

### 6.8 失敗とリトライ（決定）

- **ライフ制にしない。ゲームオーバーをなくす。**
- 水たまりに落ちる・障害物に当たる → 0.5秒よろける。**直前の安全な場所から再開**（復帰1.5秒以内）
- ステージの途中でやめても、**次に開いたら同じステージの最初から**（途中再開は作らない。2〜3分なので不要）

### 6.9 評価とごほうび（決定）

| ★の数 | 条件 |
|---|---|
| ★★★ | 算数を**全問1回目で正解** |
| ★★ | まちがいが 1〜2問 |
| ★ | クリアした（何回まちがえても） |

- ごほうびは**ランドセルにたまるシール**。ステージごとに絵柄が違う（1枚目＝いえのかぎ、4枚目＝さんかく など）
- **他人と比べる表示は出さない**（ランキングなし）
- コインは1ステージ内の小さな達成感のみに使い、累計で何かを買わせたりはしない（MVPでは）

## 8. データ要件

### 8.1 ユーザーの識別（決定）

**Googleログインは使わない。名前を選ぶ方式にする。**

理由：
- 学校の共有iPad／共有アカウントだと Google の個人識別が当てにならない
- ウェブアプリのアクセス範囲を「全員」にすると `Session.getActiveUser().getEmail()` は**空文字になる**
- 1年生にログイン操作は無理

仕様：
- 事前にスプレッドシートへ**クラス名簿**（ニックネーム）を登録しておく
- URLのクエリでクラスを指定する（`?class=1-2`）。Googleサイトのページごとに貼り分けられる
- 端末に前回の名前を覚えさせる（後述の制約により**当てにならない前提**で、毎回の名前選択を基本動作にする）

**個人情報の扱い（決定）**：本名・生年月日・写真を入れない。**ニックネームのみ**。
成績はクラス内で本人と先生・保護者だけが見るものとし、シート自体を共有しない。

### 8.2 スプレッドシート設計（決定）

| シート | 列 | 用途 |
|---|---|---|
| `classes` | `class_id`, `class_name`, `active` | クラス一覧 |
| `players` | `player_id`, `class_id`, `nickname`, `order`, `active` | 名簿 |
| `progress` | `player_id`, `stage_id`, `cleared`, `best_stars`, `best_time_ms`, `play_count`, `miss_count`, `updated_at` | 進捗（1人×1ステージで1行） |
| `sessions` | `ts`, `player_id`, `stage_id`, `stars`, `time_ms`, `q_total`, `q_first_try_ok`, `unit` | 1プレイ1行の要約（成績ページの元データ） |
| `attempts` | `ts`, `player_id`, `stage_id`, `unit`, `expr`, `answer`, `chosen`, `ok`, `ms` | **任意・既定オフ**。1問1行。v2の分析用 |

`attempts` を既定オフにするのはGASのクォータ対策（§10.3）。

### 8.3 保存のタイミング（決定）

| タイミング | やること |
|---|---|
| ゲーム開始時 | 進捗を1回読む（`progress` の自分の行すべて） |
| ステージクリア時 | 1回だけ書く（`progress` 更新＋`sessions` 追記） |
| **プレイ中** | **通信しない**（1問ごとの送信は禁止） |

- 保存は**非同期**。保存中もゲームは進む。**保存の失敗でゲームを止めない**
- 失敗したら端末内のキューに積み、次の通信成功時にまとめて送る
- 保存中は画面すみに小さく「ほぞん中…」を出す（子どもには見せなくてよい大きさ）

## 9. 非機能要件

| 分類 | 要件 |
|---|---|
| 性能 | iPad 第7世代クラスで **60fps**。60fpsを割るフレームが全体の5%未満 |
| 起動 | URLを開いてから遊べるまで **3秒以内**（GASのHTML配信が遅いので要計測） |
| 通信 | 進捗の読み込みが3秒で返らなければ、**オフラインのまま開始**してよい |
| 文字 | 1年生が習っていない漢字を使わない＝**全ひらがな＋わかち書き**。カタカナは「ステージ」等の最小限 |
| 色 | 正解・不正解を**色だけで伝えない**（○×の記号と音を必ず併用） |
| 音 | 最初のタップ後に鳴る（ブラウザの制約）。**音を切るボタンを用意**（教室での利用） |
| 操作 | タップ対象は48px以上、主要ボタンは80px以上 |
| 画面 | 横向き推奨。縦向きでも遊べる（操作ボタンを画面下にまとめ直す） |
| 依存 | **外部ライブラリを使わない**（前作と同じ方針。CDNは学校ネットワークで塞がれることがある） |
| 画像 | 外部画像ファイルを置かない。**Canvas描画かインラインSVG**で作る（§10.2） |
| プライバシー | 個人情報を保存しない。外部への通信はGoogle以外に一切しない |

## 10. GASアーキテクチャと制約

### 10.1 構成（決定）

```
プロジェクト（Apps Script）
├─ Code.gs          doGet / API（getRoster, getProgress, saveResult）
├─ Sheet.gs         スプレッドシート読み書き
├─ index.html       ページの骨格（<?!= include('...') ?> で結合）
├─ style.css.html   スタイル
├─ game.js.html     ゲーム本体（ループ・物理・描画）
├─ math.js.html     出題ロジック
├─ stages.js.html   ステージ定義（データ）
└─ admin.html       おとなのページ（v1.0）
```

`doGet` は**必ず**次を満たすこと：

```javascript
function doGet(e) {
  return HtmlService.createTemplateFromFile('index')
    .evaluate()
    .setTitle('つうがくろジャンプ')
    .addMetaTag('viewport', 'width=device-width, initial-scale=1, maximum-scale=1')
    .setXFrameOptionsMode(HtmlService.XFrameOptionsMode.ALLOWALL); // ← Googleサイト埋め込みに必須
}
```

デプロイ設定（決定）：**実行するユーザー＝自分**、**アクセスできるユーザー＝全員**。
これで子どもはGoogleログインなしで遊べ、シートへの書き込みは作成者の権限で行われる。

### 10.2 GASの制約と、それへの対応

| 制約 | 影響 | 対応 |
|---|---|---|
| `google.script.run` は**往復0.3〜1秒** | ゲームループで呼ぶと確実にカクつく | **ループ内から呼ばない**。開始時と終了時のみ（§8.3） |
| HtmlService は**サンドボックスiframe**で動く | Googleサイトに貼ると iframe が2重になる | `ALLOWALL` 必須。`window.parent` に依存しない |
| **localStorage が消える／使えないことがある** | Safari の ITP で、埋め込みiframe内のストレージは7日で消える・ブロックされることがある | **進捗の正本はスプレッドシート**。localStorageはキャッシュ扱いで、消えても壊れない設計にする |
| 静的ファイルの置き場がない | 画像・音のファイルを置けない | 絵は Canvas／SVG で描く。音は WebAudio で合成するか、短い data URI |
| `.html` ファイルにサイズ実質上限あり・エディタが重くなる | 1ファイル肥大で開発が止まる | 上記の通りファイル分割。**clasp でローカル開発**し、Gitで管理する |
| 同時実行数の上限（30程度） | クラス30人が一斉に開始すると詰まる | 開始時の読み込みを軽く（自分の行だけ）。詰まったらオフライン開始にフォールバック |
| スクリプト実行時間の日次上限（無料90分／Workspace 6時間） | ログを細かく送ると枯渇する | `attempts` を既定オフ。1回の保存を0.5秒以内に抑える |
| シートへの同時書き込み | 行が壊れる・上書きされる | `LockService.getScriptLock()` を10秒待ちで使う。書き込みは `appendRow` か範囲一括 |
| `Session.getActiveUser()` が空 | ユーザー識別できない | §8.1 の名前選択方式（そもそも使わない） |
| 音の autoplay 制限 | 最初の音が鳴らない | 最初のタップで AudioContext を resume。埋め込み iframe に `allow="autoplay"` |

### 10.3 APIの形（暫定）

| 関数 | 引数 | 返り値 | 呼ぶタイミング |
|---|---|---|---|
| `getRoster(classId)` | クラスID | `[{player_id, nickname}]` | 名前選択画面 |
| `getProgress(playerId)` | プレイヤーID | `[{stage_id, cleared, best_stars, best_time_ms}]` | ステージ選択画面 |
| `saveResult(payload)` | `{player_id, stage_id, stars, time_ms, q_total, q_first_try_ok}` | `{ok:true}` | クリア時（1回） |

`saveResult` は**同じ内容を2回送られても壊れないこと**（再送があるため）。
`player_id + stage_id + ts` で重複判定する。

**開発の進め方（決定）**

- M0〜M2 は**素のHTML/JSでローカル開発**する。GAS化はM3までやらない（GASエディタで作り込むと手が止まる）
- ローカルの `index.html` と GAS版でコードを共有できるよう、GAS固有の処理は**1ファイルに閉じ込める**
  （`api.js.html`：ローカルではダミー応答、GASでは `google.script.run` を呼ぶ）
- `clasp push` でデプロイ。ソースはこのリポジトリで管理する

**検証ツール（前作の `tools/layout-sim.js` の作法を引き継ぐ）**

`tools/stage-check.js` を作り、ステージ定義から次を自動で確かめる：

- 問題が見えてから足場に届くまでの秒数（§12の4.0秒を満たすか）
- 3つの足場すべてにジャンプで届くか（届かない配置の検出）
- 正解位置の左／中／右の分布
- 1ステージの想定所要時間
